# 世界ごとに変わるもの／変わらないもの

ワールドが毎回作り直されるなら、シナリオと「クリアに必要なもの」も毎回変わってほしい。
だが無軌道に変わると難度も所要時間も制御できない。

そこで**変えてよいものと、絶対に変えないものを分ける。**
変えてよい側だけをローカル AI に書かせ、返ってきたものは Script が検算して直す。

## 0. 唯一の原則

> **AI は一度も load-bearing にならない。**

戦記（`chronicle_ai.gd`）で既にこの形になっている。守っているのは 3 つ。

1. **構造はゲームが作る。** クエストの骨格・個数・配置・難度は生成器が決める。
   AI が触るのは**名前と意味づけ（表示用の文字列）だけ**。
2. **AI が居なくても成立する。** Ollama が止まっていても、返事が遅くても、
   壊れた JSON が返っても、そのランは普通に遊べて普通に勝てる。
   テンプレート（語彙表 × `DetRng`）が常に先に走り、AI は届いたら差し替えるだけ。
3. **決定性の外に置く。** AI の出力は乱数列にも保存にも入らない。
   同じシードから同じ世界・同じ封・同じ配置が出る。**違うのは呼び名だけ。**

この 3 つを守るかぎり、AI は「もっと広い範囲を引ける乱数」として扱える。
実際、位置づけはそれで正しい。壊れたら乱数表に落ちる、というだけ。

## 1. 三層に分ける

| 層 | 誰が決める | 例 |
| --- | --- | --- |
| **骨格（不変）** | 生成器（`DetRng`） | 封は 3 つ / 危険度の帯に 1 つずつ / 城の主を倒せば終わり / レベルと装備は失う / 資源は必ず入る |
| **肉づけ（可変）** | ローカル AI（失敗時はテンプレート） | 封の名、主の呼び名、世界の名、町の名、町人の一言、「なぜそれが要るのか」の一文 |
| **検算（修正）** | Script | 文字数・禁止語・必須項目・重複・数値の混入をすべて落とす |

**数値は絶対に AI に決めさせない。** 返してきても捨てる。
1 点の atk がボス到達率を 2 倍動かすことを実測で知っているので、
ここを言葉の生成器に触らせる理由が無い。

## 2. 骨格の案

### 推奨: 三つの封

- 城の主は **3 つの封**に守られていて、封が残っているあいだは倒せない。
- 封は危険度の帯ごとに 1 つずつ、**洞の最深部**に置く（低 2〜4 / 中 5〜7 / 高 8〜9）。
- 封の在り処は**町で聞ける**。これで町に寄る理由が生まれる。
- 3 つ解いてから城へ入る。解かずに入れば主は無敵で、逃げるしかない。

固定するのは **数（3）と帯（低・中・高）** だけ。ここが固定なら、
1 ラン の長さと難度曲線が保証される。名前と由来は毎回変わってよい。

寄り道（洞）が本筋になるのが利点で、いま「行かなくても城に着ける」ので
洞に入る理由が宝箱しかない。封を置けば、寄り道が**必須だが順番は自由**になる。

### もっと意外な案（併用もできる）

- **入城の条件**：城に入るのに、そのランで手に入れたものを差し出す
  （装備を 1 つ、ゴールド、道具）。**永久資産（熟練・技・資源・名簿）には触れない。**
  ※初版では「熟練を 1 段返す／資源を払う」と書いていたが、これは決めごと違反
  だったので取り下げた。あわせて「失うことが主題」という記述も消した（根拠が無い）。
- **偽の主**：手掛かりが足りないまま城へ行くと、主に見えるものと戦わされる。
  勝っても生還にならない（世界は閉じる）。**情報を集める意味**が生まれる。
- **世界の寿命**：世界は N 歩で閉じる。急ぐか寄るかが常に賭けになる。
  ただし難度曲線を「距離」ではなく「経過」で組み直すことになるので重い。

## 3. AI に投げるもの／返させるもの

事実（ゲームが確定させた構造）だけを渡し、文字列だけを受ける。
`Chronicle.facts_for_llm()` と同じ作り。

```
渡す（構造）                     返させる（表示用の文字列だけ）
{
  "seals": 3,                    {
  "bands": [3, 6, 9],              "world_name": "…",
  "biomes": ["草原","山","雪"],     "boss_name": "…",
  "boss_kind": "巨躯",              "seals": [
  "towns": 4                          {"name":"…", "why":"…"},
}                                     …3つ
                                    ],
                                    "rumor": "…"
                                  }
```

**ID はゲームが発行する。** AI が id を返してきても使わない。
名前と id を AI に握らせると、同じ名前で違う効果のものが並ぶ事故が起きる。

## 4. Script の検算（ここが実装の本体）

返ってきた 1 件ごとに通す。1 つでも落ちたらその項目だけテンプレートに差し替える
（全部捨てない。1 つの封の名が変でも、他の 2 つは使える）。

- **必須キーがあるか**。無ければ却下。
- **文字数**。画面幅で切る（封の名は 10 文字、一文は 34 文字。`PixelUI.wrap` の実測値）。
- **禁止語**。他社作品の固有名詞リストと突き合わせる。**ここは必ず要る。**
  初版で呪文名に DQ の名前をそのまま置いた経緯があり、AI は平然と同じことをする。
- **数値の混入**。数字を含む項目は却下（「HP300 の主」などを書かせない）。
- **重複**。3 つの封が同じ名前になったら 2 つ目以降をテンプレートへ。
- **記号・英語・思考の断片**。`ChronicleAI._clean()` と同じ処理を共有する。

落ちた理由は必ず記録する（`--ai-debug`）。黙って落とすと、
「AI を繋いだのに文章が変わらない」の原因が分からなくなる。

## 5. 待たせない

世界を作るのはランの開始時で、そこは唯一「数秒待てる」場所ではない
（拠点で決定を押した直後に固まる）。だから**待たせない**。

1. 生成器がテンプレート名で世界を完成させる → すぐ遊べる
2. 同時に AI へ投げる
3. 数秒後に届いたら、**表示だけ**差し替える（構造は動かないので安全）
4. 届かなければテンプレートのまま

封の名前が最初の数秒だけ仮名でも、遊びは何も変わらない。
**構造を先に確定させておくから、これが成立する。**

## 6. 段取り

1. 骨格（封 3 つ・帯ごとに配置・城の扉の条件）を生成器に入れる。**AI は無し。**
   テンプレート語彙表 × `DetRng` で名前を作る。ここまでで遊べる状態にする。
2. 検算層（`quest_text.gd`）を単体で作り、テストを書く。
   壊れた入力・禁止語・長すぎる文字列を食わせて、必ずテンプレートに落ちることを確認。
3. AI 接続（`ChronicleAI` を一般化して、事実 → 文字列の窓口を 1 本にする）。
4. 町の「聞き込み」を作る（封の在り処を教える）。
5. 難度の測り直し（`tests/balance.gd` を世界の踏破率に組み替える）。

**1 が終わった時点で 2 以降が全部無くてもゲームは完成している**、という順番にする。
