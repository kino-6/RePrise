# 世界ごとに変わるもの／変わらないもの

ワールドが毎回作り直されるなら、シナリオと「クリアに必要なもの」も毎回変わってほしい。
だが無軌道に変わると難度も所要時間も制御できない。

そこで**変えてよいものと、絶対に変えないものを分ける。**
変えてよい側だけをローカル AI に書かせ、返ってきたものは Script が検算して直す。

## 0. 唯一の原則

> **AI は一度も load-bearing にならない。**

戦記（`chronicle_ai.gd`）で既にこの形になっている。守っているのは 3 つ。

1. **構造はゲームが作る。** クエストの骨格・個数・配置・難度は生成器が決める。
   AI が触るのは**名前と意味づけ（表示用の文字列）だけ**。
2. **AI が居なくても成立する。** Ollama が止まっていても、返事が遅くても、
   壊れた JSON が返っても、そのランは普通に遊べて普通に勝てる。
   テンプレート（語彙表 × `DetRng`）が常に先に走り、AI は届いたら差し替えるだけ。
3. **決定性の外に置く。** AI の出力は乱数列にも保存にも入らない。
   同じシードから同じ世界・同じ封・同じ配置が出る。**違うのは呼び名だけ。**

この 3 つを守るかぎり、AI は「もっと広い範囲を引ける乱数」として扱える。
実際、位置づけはそれで正しい。壊れたら乱数表に落ちる、というだけ。

## 1. 三層に分ける

| 層 | 誰が決める | 例 |
| --- | --- | --- |
| **骨格（不変）** | 生成器（`DetRng`） | 低・中・高の 3 拍 / 目的地 / 依存関係 / 正解 / 城の条件 / ボスへの影響 |
| **肉づけ（可変）** | ローカル AI（失敗時はテンプレート） | 目的の名、主の呼び名、世界の名、町人の余談、「なぜそれが要るのか」の一文 |
| **検算（修正）** | Script | 文字数・禁止語・必須項目・重複・数値の混入をすべて落とす |

**数値は絶対に AI に決めさせない。** 返してきても捨てる。
1 点の atk がボス到達率を 2 倍動かすことを実測で知っているので、
ここを言葉の生成器に触らせる理由が無い。

## 2. 骨格の文法

固定するのは「封」という設定ではなく、次の**攻略の拍**。

```
門
 ├ 低危険度 ──┐
 ├ 中危険度 ──┼─ 城の条件 ─ 主
 └ 高危険度 ──┘
```

- **低・中・高に目的がある。** 序盤だけで終わる当たり世界や、高地だけを往復する
  外れ世界を作らない。
- **城までに 1 回以上の判断がある。** 順番、経路、二者択一、聞き込みのどれか。
- **攻略上の事実は Script が言う。** AI の台詞は事実の後ろに添える余談。
- **必須洞は最大 3。** 1 ランの長さを今の全周方針から大きく外さない。
- **永久資産を条件や代償にしない。** 使うならラン内の物だけ。

`src/quest/quest_generator.gd` はこの文法から 4 型を生成する。

### 型 A: 三つの封（自由順）

- 城の主は **3 つの封**に守られている。
- 封は危険度の帯ごとに 1 つずつ、**洞の最深部**に置く（低 2〜4 / 中 5〜7 / 高 8〜9）。
- 封の在り処は**町で聞ける**。これで町に寄る理由が生まれる。
- 3 つ解いてから城へ入る。順番は自由。

判断は「どの順で回り、どこで町へ寄るか」。もっとも素直で、初回向け。

### 型 B: 継がれる火（分岐つき連鎖）

- 低地の洞で火種を回収する。
- 中地で **町の炉へ運ぶ安全路**か、**洞の試練で鍛える危険路**を選ぶ。
- 高地で灯台を起こすと城が開く。

判断は安全な長旅か、短いが厳しい戦闘か。同じ「三地点」でも依存関係が直列になる。

### 型 C: 二つの盟約（2 of 3）

- 低・中・高に守護者が 1 体ずついる。
- 三つのうち **二つ**と盟約を結べば城へ入れる。
- 選ばずに残した守護者の特性（毒 / 速さ / 守り）が城の主に残る。

判断は「自分の編成がどのボス特性を許せるか」。全部回ることもできるが、
時間と消耗を払う。特性と数値の対応は Script が決め、AI には触らせない。

### 型 D: まことの遺物（調査か総当たり）

- 低・中・高の洞に候補が 1 つずつあるが、正解は 1 つ。
- 町の証言を 2 本集めると、偽物を 2 つ除外できる。
- 聞かずに洞を総当たりしても勝てる。

判断は情報へ寄るか、腕力で洞を回るか。正解と証言の対応は `DetRng` が先に決める。
**AI に証言の事実を書かせない。** Script が「○○は偽物だ」と組み、その後ろに
AI の余談を添える。

サンプルは `docs/quest_samples.md`。

### 現在の実装境界

- **型 A（三つの封）**は `WorldGenerator`・洞の最深部・城の扉・町の聞き込みまで
  ゲーム本体に接続済み。
- **型 B〜D**は `QuestGenerator` が決定的なグラフを作り、現行 31 世界へ割り当てて
  検算できる試作段階。専用の進行状態・イベント・ボス特性はまだ本体へ接続していない。
- `QuestText` は代替文と AI 候補の検算まで。Ollama への送信はまだ行わない。

先に型と境界を固め、B〜D を一度に本体へ入れない。型ごとに自動プレイの方針と
勝率の測り方が違うため、1 型ずつ接続して `balance.gd` を測る。

2026-07-30 の 200 ラン実測では、直行 0% 勝 / 封だけ 10% 勝 / 全周 14% 勝。
封を回る意味は出ており、道具も町も使わない自動操縦の下限として設計帯に収まる。

## 2.1 面白さの検算

文章が良くても、次を満たさない骨格は採らない。

1. 城までに**異なる二つ以上の行動方針**がある。
2. 町へ寄ると経路・相手・正解のどれかが変わる。
3. 低・中・高の目的があり、難度曲線を飛ばさない。
4. AI の全出力を空にしても、目的と正解が分かり、勝てる。
5. 同じシードなら型・配置・正解・ボス特性が一致する。
6. 誤った AI 文を全部採用しても、数値・解放条件・正解は変わらない。

## 3. AI に投げるもの／返させるもの

事実（ゲームが確定させた構造）だけを渡し、文字列だけを受ける。
`Chronicle.facts_for_llm()` と同じ作り。

```
渡す（構造）                     返させる（表示用の文字列だけ）
{
  "archetype": "two_pacts",       {
  "decision": "choose_two...",      "world_name": "…",
  "boss_kind": "巨躯",               "quest_title": "…",
  "objectives": [                    "boss_name": "…",
    {"kind":"defeat_guardian",       "objective_names": ["…","…","…"],
     "band":"low",                   "objective_reasons": ["…","…","…"],
     "biome":"wetland"},             "rumor_flavor": ["…","…","…"]
    …                              }
  ],
  "rumor_flavor_count": 3
}
```

**ID は AI に渡さず、返させない。** 配列の順序は Script が確定する。
`facts_for_ai()` は `site_id`・依存関係・正解・ボス効果を除いてから渡す。

## 4. Script の検算（ここが実装の本体）

返ってきた 1 件ごとに通す。1 つでも落ちたらその項目だけテンプレートに差し替える
（全部捨てない。1 つの封の名が変でも、他の 2 つは使える）。

- **必須キーがあるか**。無ければ却下。
- **文字数**。画面幅で切る（封の名は 10 文字、一文は 34 文字。`PixelUI.wrap` の実測値）。
- **禁止語**。他社作品の固有名詞リストと突き合わせる。**ここは必ず要る。**
  初版で呪文名に DQ の名前をそのまま置いた経緯があり、AI は平然と同じことをする。
- **数値の混入**。数字を含む項目は却下（「HP300 の主」などを書かせない）。
- **重複**。目的が同じ名前になったら 2 つ目以降をテンプレートへ。
- **記号・英語・思考の断片**。`ChronicleAI._clean()` と同じ処理を共有する。
- **余計なキーは読まない。** AI が `gate`、`reward`、`truth_node` を返しても捨てる。

落ちた理由は必ず記録する（`--ai-debug`）。黙って落とすと、
「AI を繋いだのに文章が変わらない」の原因が分からなくなる。

この検算の試作は `src/quest/quest_text.gd`。攻略に必要な証言は
`critical_lines()` が Script の事実から組む。

## 5. 待たせない

世界を作るのはランの開始時で、そこは唯一「数秒待てる」場所ではない
（拠点で決定を押した直後に固まる）。だから**待たせない**。

1. 生成器がテンプレート名で世界を完成させる → すぐ遊べる
2. 同時に AI へ投げる
3. 数秒後に届いたら、**表示だけ**差し替える（構造は動かないので安全）
4. 届かなければテンプレートのまま

目的の名前が最初の数秒だけ仮名でも、遊びは何も変わらない。
**構造を先に確定させておくから、これが成立する。**

## 6. 段取り

1. 4 型の骨格と世界への割り当てを生成器に入れる。**AI は無し。**
   テンプレート語彙表 × `DetRng` で表示文を作る。ここまでで遊べる状態にする。
2. 検算層（`quest_text.gd`）を単体で作り、テストを書く。
   壊れた入力・禁止語・長すぎる文字列を食わせて、必ずテンプレートに落ちることを確認。
3. AI 接続（`ChronicleAI` を一般化して、事実 → 文字列の窓口を 1 本にする）。
4. 町の「聞き込み」を作る（Script の重要文 + AI の余談）。
5. 難度の測り直し（`tests/balance.gd` を世界の踏破率に組み替える）。

**1 が終わった時点で 2 以降が全部無くてもゲームは完成している**、という順番にする。
