# 潜る理由（前提の案）

**この文書は提案で、確定ではない。** 作品名とキャッチコピーはユーザーの領分なので
ここでは触れない。ここで決めたいのは「なぜ毎回もぐるのか」だけ。

設定を後から足すと、たいてい仕組みと噛み合わずに浮く。だからここでは
**すでに動いている仕組みを説明できること**を条件にした。逆に言えば、
仕組みを変えないかぎり、この前提は差し替えても壊れない。
文言は `src/game/lore.gd` に集めてあるので、気に入らなければそこだけ書き換えればよい。

## 説明したい仕組み（実装済み）

| 仕組み | どこ |
| --- | --- |
| ランのたびにレベルが 1 に戻る | `GameState.start_run()` |
| 装備とゴールドは持ち帰れない | `data/equipment.json` の先頭コメント |
| 職業ごとの熟練と覚えた技は残る | `PartyMember.mastery_points` / `learned` |
| 資源（恒久通貨）は全滅しても必ず入る | `GameState.end_run()` |
| 資源で砦を強化し、仲間を迎える | `data/upgrades.json` / `recruit()` |
| 主（ボス）は潜るたびに別のものになる | `data/monsters.json` の boss 群 |
| 毎ラン初期装備が支給される | `_grant_starting_gear()` |
| 階の並びも地形も毎回変わる | `DungeonGen` |

## 案

砦の下に、底の見えない縦穴がある。**奈落**と呼ぶ（`data/monsters.json` に
すでに「奈落の番人」がいるので、新しい固有名詞は増やさない）。

奈落は**降りるたびに作り直される**。同じ道は二度と無く、底にいる主も毎回別のものになる。
だから「前回の続きから」は無い。毎回、地下 1 階から始まる。

奈落は、そこで起きたことを外へ出さない。潜った者が地下で得た力も、拾った得物も、
地上へ戻った瞬間に奈落へ返る。**だが体が覚えた手つきだけは返らない。**
記憶ではなく癖だからだ。何度も剣を振った腕は、レベルが 1 に戻っても振り方を忘れない。

—— これが「レベルと装備は失い、熟練と技は残る」の理由になる。
熟練が職業ごとに別勘定なのも、覚えた技が転職しても消えないのも、
どちらも「体が覚えたもの」で説明が付く。

奈落から吹き上がってくるものを、砦は**資源**として受けている。砦はそれで建っている。
潜れば必ず何かは持ち帰るので、全滅したランでも資源は入る。
逆に、誰も潜らなくなれば砦は保たない。**それが毎回もぐる理由。**

## 何を書かないか

- **世界の広さ、国、歴史**は書かない。画面に出ないものを設定しても、
  プレイヤーには存在しないのと同じで、戦記 AI が拾って矛盾を作るだけ悪い。
- **主人公たちの過去**も書かない。名簿は資源で増えるので、人数も顔ぶれも
  プレイヤーごとに違う。全員に共通する過去は作れない。
- **奈落の正体**は決めない。決めた瞬間に「解決したら終わり」になるが、
  このゲームは終わらない構造をしている。

## 画面に出す量

前提は 3 か所にだけ出す。多いと説明くさくなる。

1. 拠点の「出撃する」を選んだときの 3 行（`stronghold_view.gd`）
2. 資源の説明の 1 行（同上）
3. 戦記 AI に渡す世界の前提（`chronicle_ai.gd`。事実ではないので `facts` には混ぜない）

タイトル画面には出さない。題字だけを置く方針は変えていない。
