# 世界へ送られる理由（前提の案）

**この文書は提案で、確定ではない。** 作品名とキャッチコピーはユーザーの領分なので
ここでは触れない。ここで決めたいのは「なぜ毎回あたらしい世界へ行くのか」だけ。

> 初版は「砦の下の縦穴へ潜る」という案だった。**ダンジョンローグライクの前提**で
> 書いてしまったもので、コンセプト（ワールドごとローグライク）とは別物だったので破棄した。
> 世界の形は `docs/world_design.md`。

設定を後から足すと、たいてい仕組みと噛み合わずに浮く。だからここでは
**すでに動いている仕組みを説明できること**を条件にした。逆に言えば、
仕組みを変えないかぎり、この前提は差し替えても壊れない。
文言は `src/game/lore.gd` に集めてあるので、気に入らなければそこだけ書き換えればよい。

## 説明したい仕組み（実装済み／実装予定）

| 仕組み | どこ |
| --- | --- |
| 世界がランごとに丸ごと作り直される | `WorldGenerator`（予定） |
| 拠点「銀の砦」だけが世界の外に在り続ける | `StrongholdView` |
| ランのたびにレベルが 1 に戻る | `GameState.start_run()` |
| 装備とゴールドは持ち帰れない | `data/equipment.json` の先頭コメント |
| 職業ごとの熟練と覚えた技は残る | `PartyMember.mastery_points` / `learned` |
| 資源（恒久通貨）は全滅しても必ず入る | `GameState.end_run()` |
| 終点の主は毎回別のものになる | `data/monsters.json` の boss 群 |
| 毎ラン初期装備が支給される | `_grant_starting_gear()` |

## 案

**銀の砦は世界の外にある。** どの世界にも属していないから、どの世界が失われても残る。
砦から見ると、世界はひとつずつ現れては閉じていく。

一行は砦から世界へ送られる。行き先はいつも**別の世界**で、同じ世界へは二度と行けない。
地形も、町の場所も、終点に居る主も、毎回違う。
—— これが「世界ごと作り直される」「主が毎回別」の理由になる。

送られた先で背負うのは**その世界の役**でしかない。だからレベルも、拾った得物も、
その世界のもの。世界が閉じれば一緒に返る。
**返らないのは、体が覚えた手つきだけ。** 記憶ではなく癖だからだ。
何度も剣を振った腕は、レベルが 1 に戻っても振り方を忘れない。

—— これが「レベルと装備を失い、熟練と技は残る」の理由になる。
熟練が職業ごとに別勘定なのも、覚えた技が転職しても消えないのも、
どちらも「体が覚えたもの」で説明が付く。

終点の主を討てば、その世界は保たれる。討てなければ世界は失われる。
**どちらでも、踏んだぶんの記録は砦へ帰る。** それが資源で、砦はそれで建っている。
—— これが「全滅しても資源が入る」の理由になる。

## 何を書かないか

- **砦がなぜ世界の外に在るのか**は決めない。決めた瞬間に「解決したら終わり」に
  なるが、このゲームは終わらない構造をしている。
- **世界どうしの繋がり、歴史、大きな敵**は書かない。世界は毎回別なので、
  またいで続く物語は原理的に置けない。置けば嘘になる。
- **主人公たちの過去**も書かない。名簿は資源で増えるので、人数も顔ぶれも
  プレイヤーごとに違う。全員に共通する過去は作れない。

## 画面に出す量

前提は 3 か所にだけ出す。多いと説明くさくなる。

1. 拠点の「出撃する」を選んだときの 3 行（`stronghold_view.gd`）
2. 資源の説明の 1 行（同上）
3. 戦記 AI に渡す世界の前提（`chronicle_ai.gd`。事実ではないので `facts` には混ぜない）

タイトル画面には出さない。題字だけを置く方針は変えていない。
