# アート統合・実プレイ監査

監査日: 2026-07-30

## 結論

キャラクターと敵の素材品質は、現行ゲームへ載せて評価できる段階にある。
ただし、生成済み素材のかなりの部分が実行時には一度も参照されていない。
現時点で先に行うべきなのは再生成ではなく、既存素材を画面へ接続し、
実寸で比較できる状態を作ること。

特に影響が大きいのは次の4点。

1. 追加NPC 12種は `assets/sprites/` まで生成されるが、町では使われていない。
2. 戦闘背景6種と戦闘FX 12種は候補止まりで、戦闘画面は階調背景と全画面フラッシュのまま。
3. 敵画像は実装済みだが、512x320の画面へ等倍表示しているため小さく、描き込みが見えない。
4. 小さい町では地図外の灰色が画面右側へ露出し、人物より先に未完成感が見える。

実プレイの代表6画面は
[`art_integration_actual_play.png`](art_integration_actual_play.png) にまとめた。

## 確認方法

- `godot --path . --accessibility disabled -- --play=120`
- `AutoPlay` が内部関数を直接呼ばず、通常の入力イベントだけで120秒操作
- 取得した99コマを目視
- 通過画面: タイトル、拠点、世界、町、メニュー、通常戦、危険度7の帝国戦、全滅結果
- 戦闘9回、ラン終了1回、装備最大6個
- 実プレイ前の `save.json` は退避し、終了後にハッシュ一致を確認して復元
- `--shot=jobmenu` で15職が現在の職業一覧に出ることも確認

アート変更はこの監査では行っていない。以下は後で実装するための指摘と完了条件である。

なお60秒以降、自動プレイが同じ町への入退場を約0.4秒ごとに繰り返した。
画面状態自体は変わるため現行の「25秒同じ画面」検査では詰まりとして扱われない。
通常操作でも起きるかは別途確認し、`AutoPlay` には2状態の反復検出を追加する。
これはアート修正には含めないが、町の連続撮影を妨げるため先に記録しておく。

## 実画面で良かった点

### キャラクター

- 白・黒・象牙を中心にした味方キャラは、青いUIと緑の地形のどちらでも輪郭が読める。
- 24x32を16x16地形へ置く寸法関係は妥当。人物が2タイルぶんの高さになるため、
  人物とマップ記号を混同しない。
- リテイクした6職は、既存の汎用ローダー
  `assets/sprites/hero_<job>.png` から読み込める状態にあり、職業データ15種も存在する。

### 敵

- 通常敵、近年風の追加敵、帝国兵、通常ボス、帝国ボスは
  `data/monsters.json` とゲーム用画像が接続されている。
- 危険度7の実戦では帝国の人型敵3体が同時に出現し、
  槍・盾・銃の輪郭は小さいながらも判別できた。
- 足元の影、被弾点滅、対象カーソルが既にあるため、画像を拡大しても
  「どこに立っているか」「誰を狙うか」の基礎は崩れない。

### 地形

- `dungeon`、`world`、`grassland`、`wetland`、`snowfield`、`volcano` は
  `tools/gen_assets.py` から `assets/tiles/` へ入り、`ExploreView.tileset_for()` で使われる。
- 草原は一目で土地が分かり、白系の主人公は実画面でも背景から分離できた。

## 問題と修正案

### P0: 町の灰色領域を消す

実プレイした幅24タイルの町では、512px画面の右側128pxが灰色のまま残った。
`TownGenerator` の町幅は20〜30タイルだが、画面は32タイル幅である。
`ExploreView` は地図外を描かず、狭い地図を左寄せするため、ルート背景が露出している。

修正案:

- 地図描画前に画面全体を黒青または生物相ごとの暗色で塗る。
- 画面より狭い地図は中央寄せする。
- 町を無理に32タイル以上へ広げない。広げるだけでは移動距離が増え、町の密度が落ちる。

完了条件:

- 20x14、24x17、30x20の町すべてで灰色が1pxも見えない。
- 小さい町が中央に見え、HUDと地図の位置がずれない。
- 同じシードの町形状と人物配置は変わらない。

### P0: 追加NPC 12種を町へ接続する

現在の `ExploreView.FOLK_LOOKS` は
`innkeeper`、`merchant`、`elder`、`scout`、`guard` の5枚しか参照しない。
今回追加した以下の12枚は `assets/sprites/` まで生成されるが、実行時参照がない。

`healer`、`blacksmith`、`miner`、`ferryman`、`farmer`、`beastkeeper`、
`mechanic`、`scribe`、`refugee`、`pilgrim`、`performer`、`imperial_officer`

実プレイした町でも旧NPCだけが並び、新しいキャラクター美術基準は町へ現れなかった。

修正案:

- NPCの機能を表す `kind` と、外見を表す `look` を分離する。
- `TownGenerator` が既存の `DetRng` で `look` を決め、
  `folk[pos]` に `{"kind": ..., "look": ..., "line": ...}` を保存する。
- 宿主や店主の機能は変えず、土地ごとの外見候補表だけを増やす。
- 例:
  - 草原: `farmer`、`healer`、`performer`
  - 湿地・水辺: `ferryman`、`beastkeeper`、`pilgrim`
  - 雪原・鉱山: `miner`、`blacksmith`、`scribe`
  - 火山・帝国圏: `mechanic`、`refugee`、`imperial_officer`

完了条件:

- 同じ世界シードではNPCの外見も一致する。
- 12町を生成したとき、追加12種のうち最低8種が実画面に出る。
- `kind` による宿・店・物知りの機能は現在と同じ。
- 外見IDが欠けても既存5種へ安全にフォールバックする。

### P0: 戦闘の敵を実寸で見せる

現在は48x48または64x64の画像を等倍表示する。
512x320の戦闘画面では、敵3体でも中央に大きな空白が残る。
帝国兵は細身なので幅20px前後に見え、顔や武装の描き分けがほぼ消える。
ボス候補も等倍では通常敵と大きさの印象があまり変わらない。

修正案:

- 敵は最近傍2倍を基本にして、配置計算、影、カーソル、ダメージ数字も
  拡大後の表示矩形を基準にする。
- 5〜6体編成だけは2段配置と個別倍率を検討する。
- 小型敵を1倍へ戻す必要がある場合は、`display_scale` をモンスターデータへ持たせる。
  倍率は整数だけに限定する。

完了条件:

- 1〜4体は2倍表示で重ならず、地平線とメッセージ窓の間へ収まる。
- 5〜6体も対象カーソル、状態表示、ダメージ数字が重ならない。
- 64x64ボスが通常の48x48敵より明確に大きく見える。
- 最近傍拡大で半端なドットを作らない。

### P0: 戦闘背景6種を使う

現在の戦闘背景はコードで描く紺色の空と生物相別の地面グラデーションだけである。
敵の足場は読めるが、草原・湿地・雪原・火山・帝国工廠の物語性がほとんど出ない。
生成済み背景候補6種は `docs/chara_image/` にあるが、
`assets/` への生成と `BattleView` からの参照がない。

修正案:

- 次のIDを生物相・場所へ割り当てる。
  - `grassland_twilight`
  - `drowned_wetland`
  - `snowfield_ruins`
  - `volcanic_caldera`
  - `dungeon_depths`
  - `imperial_foundry`
- `tools/gen_assets.py` から `assets/backgrounds/battle_<id>.png` を生成する。
- `BattleView._draw_backdrop()` は画像を優先し、欠けた場合だけ現在の階調背景へ落とす。
- 敵の影は残す。背景画像だけでは足元位置が曖昧になる。

完了条件:

- 6背景すべてを実際の戦闘UIと敵1・3・6体で撮影する。
- 敵の後ろ55%は十分暗く、輪郭が背景へ沈まない。
- 生物相IDが未知でも現在の階調背景で戦闘が成立する。

### P1: 強いキャラクターデザインをUIでも見せる

探索中の24x32は読みやすい一方、細部を鑑賞できる場所が拠点の48x64表示しかない。
拠点右上の人物は情報欄に対して小さく、リテイクで追加した角、仮面、有機襟が
実プレイではほぼ見えない。戦闘画面には味方画像が出ないため、職業画像の露出時間も短い。

修正案:

- 拠点の人物表示を最近傍3倍の72x96へ上げる。
- 職業選択画面でも、カーソル中の職業画像を同じ倍率で表示する。
- テキストと重なる場合は倍率を下げず、人物用領域を先に確保する。
- 全15職の撮影を自動化し、同じ枠内で輪郭を比較する。

完了条件:

- 15職すべてで人物が枠外へ出ず、名前・能力・解放条件と重ならない。
- 遊び人の仮面、銃士の刻印銃、賢者の枝角冠が等倍画面で区別できる。
- `--shot=job` がタイトルではなく職業画面を確実に撮る。

### P1: 戦闘FX 12種を技へ接続する

現在の攻撃結果は効果音、敵の点滅、全画面フラッシュ、文章が中心で、
生成済み戦闘FX 12種は候補止まりである。

修正案:

- 能力データに見た目専用の `fx_id` を追加する。
- `slash`、`thrust`、`gunshot`、`explosion`、`fire`、`ice`、`bolt`、
  `heal`、`poison`、`sleep`、`buff`、`debuff` を4コマ再生する。
- 効果は結果計算後に再生するだけとし、ダメージ、対象、乱数順を変えない。
- 未指定または画像欠落時は現在の点滅とフラッシュだけで進行する。

完了条件:

- 12種をコマ送り撮影できる。
- 範囲技は対象位置ごとに出るが、戦闘ロジックの乱数消費は増えない。
- オート戦闘でも演出待ちが累積しすぎない。

### P1: イベントFXとトランジションを接続する

イベントFX 4種とトランジション4種は `assets/` に生成済みだが、
`src/` と `data/` からの参照がない。現在の画面切り替えは暗転、
戦闘開始は白い点滅だけである。

修正案:

- 世界門、封印解除、年代記、帝国警報へイベントFXを割り当てる。
- 通常暗転を全廃せず、重要な場面だけトランジションを選ぶ。
- トランジション選択はイベント種別で固定する。ランダム選択は不要。
- 画像欠落時は現在の `_fade_to()` と `_flash_into_battle()` に戻す。

完了条件:

- 8アトラスすべてに最低1つの実行時参照がある。
- 画面切り替え中に入力が次画面へ抜けない。
- 演出の有無でセーブ、乱数、行動順が変わらない。

### P2: 候補止まりの帝国・装飾素材を世界へ置く

以下はまだ候補だけで、ゲーム用画像、データ、実行時参照のいずれかが欠けている。

- 帝国系味方職6種
- 飼育された帝国魔獣6種
- 帝国施設装飾12種
- 町専用タイル
- クエスト封印アイコン

これらは単独で追加せず、帝国工廠または魔獣収容区という場所の実装と同時に入れる。
装飾だけを既存の草原へ散らすと、世界観の説明より先に見た目が混ざる。

完了条件:

- 帝国系味方職を入れる場合は職業能力・解放条件・表示語も同時に定義する。
- 帝国魔獣は帝国系の出現表にだけ入り、通常生物相へ無条件に混ざらない。
- 施設装飾は通行判定と描画層を持ち、床タイルへ焼き込まない。
- 町専用タイルは現在の町生成の9タイル順と一致させる。

## 実装順

1. 町の灰色領域を消す。
2. NPCの `kind` と `look` を分け、追加12種を決定的に配置する。
3. 戦闘の敵を整数倍で拡大する。
4. 戦闘背景6種を生成器と描画へ接続する。
5. 拠点・職業選択の人物表示を大きくする。
6. 戦闘FXを能力へ接続する。
7. イベントFXとトランジションを重要場面へ接続する。
8. 帝国職・帝国魔獣・施設装飾を専用ステージと同時に実装する。

この順なら、最初の4項目だけで現在ある画像の大半を実プレイで評価できる。
そこで初めて、残った画風差や個別アセットのリテイクを判断する。

## 実装時に守ること

- 見た目の抽選にも `DetRng` だけを使う。
- 画像演出をダメージ計算やクエスト構造へ入れない。
- `assets/` を直接編集せず、`tools/gen_assets.py` を更新する。
- ドット画像の表示倍率は整数にする。
- 画像欠落時のフォールバックを残し、アート未生成でもゲームを成立させる。
- 見た目を変えた項目ごとに実画面を撮り、候補画像だけで完了判定しない。

## 撮影系の補足

`--shot=job` は `_enter_stronghold()` の暗転完了前に
`debug_open_job_menu()` を呼ぶため、現在はタイトル画面を保存することがある。
職業アートの統合確認に必要なので、実装作業時に撮影専用経路で暗転完了を待つか、
撮影時だけ確定状態へ直接切り替える。通常プレイの遷移ロジックは変更しない。
