# 画面トランジションの設計 ―― 遭遇の閃光をやめる

「遭遇時の閃光が強すぎる。往年の RPG のトランジションを調べて学ぶ」への回答。

## 何が間違っていたか

これまでの遭遇演出はこうだった。

    白 0% → 85% → 0% → 85% → 0%（各 0.05 秒）→ 黒へ暗転

**白を 2 回叩きつけていた。** 眩しいだけで、しかも狙っていた「SFC 後期」から
いちばん遠い。理由は実装ではなく**時代の取り違え**にある。

## 実機が持っていた道具

SFC（S-PPU）が画面全体に掛けられた効果は、おおよそ次の 4 つ。

| 道具 | レジスタ | できること |
|---|---|---|
| モザイク | `$2106` | 画面を 1〜16 画素の角ブロックへ粗くする。背景ごとに掛けられる |
| 明度 | `$2100`（INIDISP） | 画面全体の明るさを **16 段**で落とす |
| 窓 | `$2126`–`$212A` + HDMA | 走査線ごとに窓の幅を変え、アイリス・カーテン・菱形に切り抜く |
| 色演算 | `$2131`/`$2132` | 固定色を加減算して画面を染める |

ここで決定的なのは **明度レジスタは「暗くする」方向にしか無い**こと。
既定が最大輝度なので、`$2100` で「白く飛ばす」ことは**できない**。
白フラッシュを出すには色演算で固定色を足すか、パレットを白に差し替えるしかなく、
どちらも「わざわざやる」部類の演出だった。だから SFC 期の画面切り替えは
**モザイクと明度落としと窓抜き**が基本語彙で、白閃光はそこに入っていない。

逆に FC は、この 4 つのうち**パレット差し替えしか持っていなかった**。
一瞬で画面を白や赤にできる唯一の手が palette flip だったので、
FC の演出は必然的に閃光へ寄る。**白く 2 回瞬く画面が「FC っぽい」のは、
趣味の問題ではなく、それが FC にできる唯一の全画面演出だったから**だ。

つまり最初の指摘――「FC な印象」――は演出の言語の問題そのものを突いていた。

## 採るもの

遭遇には**モザイク**を使う。理由は 3 つ。

1. **実機の第一語彙**。SFC を代表する全画面効果で、遭遇・場面転換の定番。
2. **画面の中身を残したまま覆える**。歩いていた地形が粗くなって溶けるので、
   「いまいた場所から引きずり込まれた」という因果が絵として繋がる。
   暗転や閃光は前後を**切る**が、モザイクは**繋ぐ**。
3. **眩しくない**。明るさの総量が変わらない。

明度は下げる方向にだけ使い、しかも **16 段に量子化する**。滑らかに補間すると
現代の CSS フェードになる。実機は 16 段しか無く、その段つきがあの手触りを作る。

## 決めごと

* **白を足さない。** 加算方向の全画面演出は入れない。
* **ブロック段は整数**（1,2,3,…,16）。中間の 3.7 画素などは実機に無い。
* **量子化した粒で刻む**。ゲーム画素（512x320）を基準に切る。
  ウィンドウ画素で切ると倍率によって粒の大きさが変わってしまう。
* **短く。** 入り 0.30 秒・戻り 0.20 秒。遭遇は 1 ラン中に何十回も通る。
  演出で待たされるのがいちばん嫌われる（`EventEffect` と同じ理由）。
* **失敗しても進行を変えない。** シェーダが使えない環境では素の暗転へ落ちる。
  演出は飾りで、乱数にもセーブにも触らない。
