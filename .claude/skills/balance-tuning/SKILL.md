# 難度を測る・動かすときの手順

数字を動かす前に読む。ここに書いてあるのは**過去に外した測り方**と、その直し方。

## 1. まず「測り方」を疑う

このリポジトリでは、**測り方が間違っていた回数のほうが、数値が間違っていた回数より多い**。

実例:

* **1 戦が長い問題。** 「敵 6 体の戦闘が 17 秒」という前提で遅延を詰めていた。
  測ったら**敵 1 体でも最長 11.9 秒**で、長さを決めていたのは手番数ではなく
  **行数**だった（1 行ごとに待っていた）。体数は原因ではなかった。
* **難度が「妥当」だった問題。** `balance.gd` が宿にも寄らず宝箱も開けない
  party を回していた。実プレイに寄せたら**勝率 33% → 63%** に跳ね、
  判定が「妥当」から「易しい」へ反転した。それまでの調整はすべて
  **実際より辛い世界**を見ていた。
* **主が関門でなかった問題。** 「主が硬すぎるか」を議論する前に主戦だけ取り出したら、
  Lv14 の万全な party が 7 体すべてに **100% 勝っていた**。

手順:

1. **仮説を数字にする。** 「6 体が長い」なら、体数ごとに測る列を足す。
2. **仮説が外れる形で出す。** 体数ごとに出せば「1 体でも長い」が見える。
   合計だけ出すと、外れていることに気づけない。
3. 外れたら**前提を捨てる**。前提に合う説明を探さない。

## 2. Sim は実プレイと同じ経路を通す

`tests/balance.gd` は本物の `BattleSystem` / `AutoTactic` / `WorldGenerator` を回す。
**ここに素朴な代用を書いた瞬間に、測っている強さと遊べる強さが別物になる。**

過去に抜けていて、後から入れたもの:

* **宿**（町の上を通ったら全回復・毒治療）。無料なので実プレイで素通りしない。
* **宝箱**（階段までの道から 4 歩以内だけ）。全部開けるのは寛容すぎ、
  0 個だと初期装備のまま 10 階を戦うことになる。
* **拾った装備を着せる**。`BestGear.plan()` を通す ―― ここに別の判断を書かない。
* **毒で手番が消えていた**（`_begin_turn` が `return` していた）。
  Sim は行動させていたので、両者がずれていた。

まだ入っていないもの: **イベント**（`EventEffects` が `GameState` を要る作り）。
crude に真似ると「実システムを回す」という前提が崩れるので、入れずに明記する。

## 3. 帯（目標値）の出どころを確認する

**前の帯（到達 28〜38%）は、壊れた Sim が出していた 35% から引かれていた。**
事故でできた辛さを設計として固定するところだった。

帯を引くときは「何を根拠に」を必ず書く。いまの帯と根拠:

```
全周（洞を全部まわる、最も手厚い遊び方）
  到達 45〜85%   旅がゲーム本体。着けないと何も始まらない
  勝利 12〜25%   主が山場。稀であるべき
```

その差（**72% 着いて 23% 勝つ ＝ 約半数が「着いたのに勝てない」**）が物語になる。

帯を外れたら `balance.gd` は**終了コード 1** で落ちる。所見を print するだけだと、
数字が動いても誰も止めず、「妥当」と言い続けているあいだに実際の難度がずれる。

## 4. 主（ボス）を強くするときは行動回数から

**1 対 4 は、数値ではなく行動回数の問題。** 23 手番の戦いで主が動けるのは 4 回ほど。
HP や攻撃力を盛ると「硬いだけの壁」になり、戦いにならない。

`Encounter` に 3 つの定数がある。**すべて実測で決める。**

```
BOSS_STAT_PERCENT   能力の倍率（階層補正は掛けない ―― 調整点が 2 か所に散る）
BOSS_AGI_FLOOR      速さの下限（山場の相手が場でいちばん鈍いのは筋が通らない）
BOSS_COST_PERCENT   行動の速さ（小さいほど何度も動く）
```

測り方:

```
godot --headless --script tests/balance.gd -- --boss=140   # 主戦だけ取り出す
godot --headless --script tests/balance.gd -- --runs=500   # 通し（Gate）
```

**感度が急峻**なので小刻みに動かす。実測の例（Lv14 の万全な party の勝率）:

```
100 / 20 / 80 → 100%     120 / 26 / 60 →  64%
110 / 24 / 70 →  95%     126 / 28 / 55 →  31%
122 / 27 / 59 →  52%     140 / 30 / 40 →   2%
```

通しでは party が傷ついて着くので、**主戦だけの勝率より通しの勝率は低く出る**
（52% → 通しで 23%）。

## 5. 見たいものによって必要な試行数が違う

* **勝率・到達率**: 1 ランに 1 回しか結果が出ないので **500 ラン**要る。
* **1 戦の長さ**: 1 ランで数十戦あるので **40 ラン**でも数百戦になる。

検討中に毎回 500 を回さない（数分かかる）。確定のときだけ 500。

## 6. 触ってはいけないもの

* **永久資産**（熟練・技・資源・名簿）で難度を調整しない。
* **利便性を損なう代償**を、ラン中であっても入れない。
* **遅延を 0 にして速くしない。** 何が起きたか読めなくなる。
  削るのではなく**束ねる**（窓 1 枚ぶんまとめて出して 1 回だけ待つ）。
